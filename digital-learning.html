SYSTEM_DOC V2.2.0

校務數位填報系統

完整部署手冊_ _

本手冊依目前程式內容整理，適用架構：

  • Google Apps Script：網頁、伺服器端驗證與資料讀寫
  • Google Sheets：帳號、學校資料、軟體效益、管考資料與操作紀錄
  • Firebase Authentication：Google 帳號登入
  • Google Drive：軟體佐證 PDF 與觀議課佐證 PDF
  • MDM 資料：可放在同一份試算表，也可指定另一份試算表

💡 SYSTEM_NOTE：本系統沒有把填報內容存進 Firestore。Firebase 在本案只負責 Google 登入與 ID Token；正式資料仍由 GAS 寫入 Google Sheets。

01 一、部署前準備

請準備：

  1. 一個負責部署的 Google 帳號。
  2. 一份 Google 試算表。
  3. 一個 Firebase 專案。
  4. 系統完整程式檔案。
  5. 若要指定 PDF 存放位置，預先建立兩個 Google Drive 資料夾。

建議部署帳號長期保留，並擁有以下資源：

  • 系統 Google 試算表的編輯權限。
  • MDM 來源試算表的檢視權限。
  • 兩個佐證資料夾的編輯權限。
  • Firebase 專案管理權限。

⚠️ Apps Script 的正式版本部署與部署者帳號綁定；若部署者帳號遭刪除，既有部署可能發生錯誤。

  • Web App 存取：任何人

03 三、建立 Firebase 專案與 Google 登入

3.1 建立 Firebase 專案

  1. 開啟 Firebase Console。
  2. 選擇「新增專案」。
  3. 輸入專案名稱並完成建立。
  4. Google Analytics 對本系統不是必要項目，可自行決定是否啟用。

3.2 建立 Firebase Web App

  1. 進入 Firebase 專案總覽。
  2. 選擇 Web 圖示 </>。
  3. 輸入應用程式暱稱。
  4. 不需要為本系統啟用 Firebase Hosting。
  5. 完成後取得 firebaseConfig。

本系統需要其中四個值：

const firebaseConfig = {
  apiKey: "...",
  authDomain: "專案ID.firebaseapp.com",
  projectId: "...",
  appId: "..."
};

3.3 啟用 Google 登入

  1. Firebase Console → Authentication。
  2. 選擇「開始使用」。
  3. 開啟「Sign-in method／登入方式」。
  4. 選擇 Google。
  5. 設為啟用。
  6. 選擇專案支援電子郵件。
  7. 儲存。

Firebase 官方說明指出，Web App 可使用 `signInWithPopup` 或 `signInWithRedirect`；本系統桌面優先使用彈出視窗，彈出視窗受阻時會改採重新導向。

3.4 Firestore 是否需要建立

不需要。本系統的資料存放位置是 Google Sheets 與 Google Drive。

專案附帶的 firestore.rules 是「拒絕所有 Firestore 讀寫」的保護規則。如果 Firebase 專案完全沒有建立 Firestore，可以略過；如果已建立 Firestore，則可視需要另外透過 Firebase CLI 部署該規則。

04 四、設定 Apps Script 指令碼屬性

Apps Script → 左側齒輪「專案設定」→「指令碼屬性」→「新增指令碼屬性」

4.1 必填屬性

屬性名稱 內容
FIREBASE_API_KEYFirebase Web App 的 apiKey
FIREBASE_AUTH_DOMAINFirebase Web App 的 authDomain
FIREBASE_PROJECT_IDFirebase Web App 的 projectId
FIREBASE_APP_IDFirebase Web App 的 appId

請直接貼值，不要加引號、逗號或 apiKey: 等文字。

4.2 試算表屬性

屬性名稱 是否必要 說明
SPREADSHEET_ID綁定式 GAS 可省略系統主要試算表 ID
MDM_SPREADSHEET_ID建議設定MDM 資料來源試算表 ID；留空則從主要試算表尋找符合格式的分頁

試算表 ID 是網址中 /d/ 與 /edit 之間的字串。

4.3 PDF 資料夾屬性

屬性名稱 用途
SOFTWARE_EVIDENCE_FOLDER_ID軟體使用效益佐證 PDF 資料夾
MONITORING_EVIDENCE_FOLDER_ID管考觀議課佐證 PDF 資料夾

資料夾 ID 是 Drive 資料夾網址中 /folders/ 後面的字串。

若不設定：

  • 第一次上傳軟體佐證時，自動建立 軟體使用效益調查_佐證資料。
  • 第一次上傳觀議課佐證時，自動建立 管考填報_觀議課佐證資料。
  • 系統會把自動建立的資料夾 ID 寫回上述指令碼屬性。

若要指定資料夾，部署帳號必須具有該資料夾的編輯權限。修改資料夾 ID 只影響之後上傳的檔案，不會自動搬移既有 PDF。

05 五、第一次初始化 Google Sheets

5.1 執行初始化

  1. 在 Apps Script 編輯器上方函式下拉選單選擇 initializeSystem。
  2. 按「執行」。
  3. 第一次執行會出現 Google 授權畫面。
  4. 使用部署帳號完成授權。
  5. 等待執行完成。
  6. 回到 Google 試算表重新整理。

初始化後會建立或補齊：

Settings UNITS Users 學校基本資料 軟體使用效益調查 管考填報 Logs

initializeSystem() 的行為是補齊缺少的工作表與欄位，不會清除既有填報資料。

5.2 特別注意

日常版本升級只需要執行「初始化工作表」。不要隨意執行：

  • 「更新學校基本資料欄位（自動備份）」
  • 「更新軟體調查欄位（自動備份）」

這兩個功能是舊版資料結構整體轉換工具，會先備份再重建原工作表，不適合一般小版本升級。v2.2.0 新增 chargingCartInventoryJson 時，只要執行初始化即可。

07 七、設定 UNITS 學校清單

UNITS 工作表欄位：

unit active
p28關西國小 TRUE
  • unit：註冊頁顯示的學校簡碼＋名稱，必須唯一。
  • active=TRUE 或留空：顯示於註冊選單。
  • active=FALSE：停止提供新帳號選取。
  • 可以直接在工作表最後新增學校，不必修改 HTML。

09 九、第一次部署 GAS Web App

Apps Script 官方流程為「部署 → 新增部署作業 → 網頁應用程式」。本專案部署設定如下：

  1. 按右上角「部署」。
  2. 選擇「新增部署作業」。
  3. 類型選「網頁應用程式」。
  4. 說明輸入版本，例如 v2.2.0 初次部署。
  5. 執行身分選「我」。
  6. 誰可以存取選「任何人」。
  7. 按「部署」。
  8. 完成必要授權。
  9. 複製結尾為 /exec 的正式網址。

為何選「執行身分：我」：

  • 所有學校共用同一份 Sheets 與 Drive 資料夾。
  • 使用者不必逐一授權 Google Sheets 與 Drive。
  • Firebase ID Token、Users 狀態、OWNER／VIEWER 與填報期限會在 GAS 後端驗證。

雖然網址設定為任何人可開啟，但除了公開設定與學校選單，資料讀寫函式都需要有效 Firebase Token；填報資料不是公開讀取。

💡 備註： /dev 是測試部署，只供有 Apps Script 編輯權限的人使用；正式分享必須使用 /exec。

10 十、加入 Firebase 授權網域

  1. 使用無痕視窗開啟 GAS /exec 網址。
  2. 開啟瀏覽器開發者工具 Console，或嘗試登入。
  3. 記下 Firebase 提示的「目前網域」。
  4. Firebase Console → Authentication → Settings → Authorized domains。
  5. 新增 GAS 實際執行頁面的完整主機名稱。

可能需要加入：

script.google.com
script.googleusercontent.com

如果錯誤訊息顯示更完整的子網域，例如：

n-xxxxxxxxxxxxxxxx-0lu-script.googleusercontent.com

請把錯誤訊息中的完整主機名稱也加入，不要包含 https://、路徑、斜線或參數。Firebase 官方說明要求加入 Web App 主機的完整網域名稱；只加入父網域不一定能涵蓋子網域。

完成後等待片刻，再重新整理頁面測試。

11 十一、Google Workspace 管理員封鎖 OAuth 的處理

如果登入畫面顯示：

已封鎖存取權
必須通過貴機構管理員的審查
錯誤 400：access_not_configured

這不是 Firebase Authorized domains 設錯，而是登入者所屬 Google Workspace 管理員封鎖了 Firebase Google 登入使用的 OAuth 應用程式。

處理方式：

  1. 請該網域管理員在 Google Admin Console 的 API 控制／應用程式存取控制中審核並允許該 Firebase OAuth 應用程式。
  2. 提供錯誤畫面中的應用程式名稱及 Firebase authDomain 給管理員。
  3. 個人 Gmail 通常不受學校 Workspace 的第三方應用程式政策限制，因此可能可以登入；這不代表學校帳號設定已完成。

即使 GAS Web App 本身選擇「任何人」，Firebase Google 登入仍然是 OAuth 流程，所以仍可能被對方網域政策阻擋。

12 十二、首次註冊、審核及校級權限

12.1 註冊

  1. 使用者開啟 /exec 網址。
  2. 按「使用 Google 帳號登入」。
  3. 第一次登入選擇學校。
  4. 帳號寫入 Users，預設狀態為 PENDING。

12.2 核准

  1. 管理員回到 Google 試算表。
  2. 開啟 Users 工作表。
  3. 點選使用者所在列任一儲存格。
  4. 選擇「📋 填報系統工具 → 核准選取的使用者」。
  5. 使用者回到等待頁按「重新檢查」。

12.3 OWNER／VIEWER

  • 同校第一位通過審核者：OWNER
  • 同校後續核准者：VIEWER
  • OWNER：在開放期間可新增、修改、刪除與上傳。
  • VIEWER：只能瀏覽、查看佐證與列印。
  • 前端會隱藏操作按鈕，後端也會再次驗證。

如需更換學校管理者：

  1. 在 Users 選取新的已核准帳號。
  2. 選擇「📋 填報系統工具 → 指定為該校填報管理者」。
  3. 同校其他已核准帳號會成為 VIEWER。

停用使用者：選取該列後執行「停用選取的使用者」。若停用的是 OWNER，系統會將管理權交給同校其他已核准帳號。

14 十四、部署後驗收清單

基本啟動

  • /exec 網址可開啟。
  • 首頁沒有「Firebase 尚未設定完成」。
  • Google 登入視窗可正常開啟。
  • iPad／手機可登入；彈出視窗失敗時可改走重新導向。

註冊與權限

  • 新帳號只能從 UNITS 選擇學校。
  • 新帳號進入等待核准頁。
  • 核准後可以進入系統。
  • 同校第一位核准者為 OWNER。
  • 同校第二位核准者為 VIEWER。
  • VIEWER 看不到送出、修改、刪除及上傳按鈕。
  • VIEWER 仍可瀏覽與列印。

填報期限

  • 開放期間 OWNER 可以儲存。
  • 尚未開始或截止後 OWNER 只能瀏覽。
  • 期限外直接呼叫後端也會被拒絕。
  • ADMIN 是否繞過期限符合 Settings 設定。

資料功能

  • 學校基本資料可儲存並再次帶回。
  • 可新增多筆載具與行動充電車。
  • 軟體品項可新增、修改、刪除與列印。
  • 軟體與觀議課 PDF 上傳到正確資料夾。
  • 管考資料可更新同校同年度紀錄。
  • MDM 期別下拉選單有資料。

15 十五、日後更新程式的正確方式

為維持同一個網址：

  1. 先備份目前 GAS 程式或建立版本紀錄。
  2. 只替換新版指定的檔案。
  3. 儲存全部程式。
  4. 如果新版增加工作表欄位，執行一次 initializeSystem()。
  5. Apps Script →「部署 → 管理部署作業」。
  6. 選取目前使用中的 Web App。
  7. 按編輯圖示。
  8. 版本選「新版本」。
  9. 填入版本說明。
  10. 按「部署」。

強烈建議：使用「管理部署作業」更新原部署，可保留原 /exec 網址。不要每次都建立另一個全新部署網址。

更新完成後建議：

  • 使用無痕視窗重新登入。
  • 桌面與 iPad 各測試一次。
  • 測試 OWNER 與 VIEWER 各一個帳號。
  • 確認 PDF 資料夾與 Logs。

SOFTWARE_EVIDENCE_FOLDER_ID 無法存取ID 錯誤或部署者無權限修正 ID 或分享資料夾給部署者
MDM 找不到有效期別表頭或欄位不足確認 A、D、E、F、G 表頭及至少一列資料
修改程式後網頁沒變正式部署仍指向舊版本管理部署作業並改用新版本
/dev 別人打不開測試網址只供編輯者分享 /exec 正式網址

瀏覽器顯示 Blocked autofocusing on an input element in a cross-origin subframe 通常只是跨網域 iframe 的自動聚焦警告，不是登入失敗的主要原因；應優先查看是否另有 unauthorized-domain、彈出視窗阻擋或 OAuth 管理政策錯誤。
